# 화면과 개입 경험

상태: 화면 설계 제안. 사용자는 각자의 브라우저에서 같은 조사방에 들어온다.

## 기본 화면

```text
┌───────────────────────────────────────────────────────────┐
│ 문제 제목 · 목표 · 참가자/AI · 연결상태 · [전체 일시정지]     │
├─────────────────────────────────┬─────────────────────────┤
│ 공동 대화                       │ 내 AI                   │
│                                 │ 저장소·연결 수준·세션    │
│ AI A 질문                       │ 조사/응답/대기 상태      │
│ AI B 조사 상태 · 근거 · 답변     │                         │
│ 개발자 공동 결정                │ 상대에게 보내는 초안    │
│                                 │ 수신자·전송 상태        │
│ 확정 기록 · 펼칠 수 있는 근거    │ [중단] [재개]           │
├─────────────────────────────────┼─────────────────────────┤
│ 공동 발언 입력                  │ 자기 AI 입력            │
│                                 │ 설명 / 방향 수정        │
├─────────────────────────────────┴─────────────────────────┤
│ 공동 조사 결과 · 미확인 항목 · 담당자 · 다음 검증            │
└───────────────────────────────────────────────────────────┘
```

레이아웃은 최초 화면 후보이며 디자인 확정안이 아니다. 작은 화면에서는 공동 대화/내 AI를 탭으로 바꾸되 전체 정지와 실제 진행 상태를 항상 확인할 수 있게 한다.

## 공동 대화창

- 발신자가 사람인지 AI인지, 소유자는 누구인지, 수신자는 누구인지 표시한다.
- 질문·답변·근거·공동 결정·방향 변경을 구분한다.
- 작성 중 표시와 영속 저장된 메시지의 상태를 구분한다.
- 도구 활동은 파일 읽기, 테스트 실행, 승인 대기, 실행 결과 등 확인 가능한 이벤트로 보여준다. 모델 내부 생각 전체를 보여준다고 약속하지 않는다.
- raw 로그는 접어두고 공유 허용된 발췌·코드 위치·실행 결과를 우선 표시한다.
- 코드 위치는 저장소별 위치를 표시한다. 상대 PC 경로를 클릭해 자기 로컬 파일로 잘못 열지 않도록 저장소·commit을 함께 보여준다.
- 근거 부족, 이전 버전, 오프라인, 미확인 결과를 상태로 표시한다. 성공 표시를 색상만으로 전달하지 않는다.

## AI 발신창

사용자가 말한 ‘AI가 입력하는 창’은 AI의 작성 과정을 관찰하는 패널이다. 수신자, 어떤 질문에 답하는지, 공유할 근거와 전송 상태를 함께 표시한다.

확정 메시지 영속 저장 이후에만 상대 처리 대상이 된다. 개인 설명·로컬 원본 출력이 그대로 발신창으로 복사되는 구조를 피한다. 최초 버전은 ‘작성 중’ 상태와 로컬 공개 검사를 마친 완성 초안을 제공한다.

token 미리보기는 후속 선택 기능이다. 공개 전 민감정보 검사를 통과한 내용만 전송하고, 자기 사용자의 초안과 상대에게 확정 공개된 메시지를 구분해야 한다. raw token을 먼저 공동 화면에 뿌리고 나중에 가리는 방식을 쓰지 않는다.

자동 전송을 기본 후보로 하되 첫 연결·민감한 발췌·공유 범위 확장은 소유자 확인을 거친다. 매 메시지 승인 방식은 관찰 부담이 커지므로 파일럿에서 자동 전송 범위와 수동 검토 필요성을 비교한다.

## 개발자 입력의 종류

| 입력 | 예 | 처리 |
|---|---|---|
| 개인 설명 | ‘접수와 완료가 왜 다른 거야?’ | 선택한 공동 메시지 snapshot을 별도 설명 session으로 전달 |
| 방향 수정 | ‘응답 성공 이후의 조회 경로부터 봐’ | 자기 AI에 명시적 intervention; 현재 run 중단 확인 후 새 turn에 반영하고 변경은 공동 기록에 남김 |
| 공동 발언 | ‘서비스 B가 기록한 작업 상태가 기준이야’ | 사람의 공개 메시지. 업무 결정이면 확인된 결정으로 기록 |
| 실행 권한 승인 | ‘이 로컬 테스트를 실행해도 돼’ | 소유자·scope·실제 명령·환경이 표시된 승인 경로 사용 |

일반 텍스트 입력으로 실행 권한 승인을 위장하지 못하게 한다. ‘설명’과 ‘방향 수정’의 선택 상태를 명확히 보여준다. 개인 문구를 공동 기록에 공개할 때는 공개할 최종 문구를 사용자가 선택한다.

‘방향 수정’은 공동 조사에 쓰는 입력이며 공개 기록에 남는 문구를 확인한 뒤 제출한다. 비공개로 고민한 원문을 공개 문구와 함께 몰래 공동 runtime에 넣지 않는다. 비공개 상담은 설명 session에서 유지하고 사용자가 선택한 실제 방향 입력만 공동 session에 적용한다.

개인 설명창은 상대에게 보이지 않는다. 설명 답변을 펼쳐보는 동안 공동 대화는 계속 갱신할 수 있지만, 화면을 읽고 있다는 이유로 정지 요청이 없어도 AI가 멈추는 것처럼 표시하지 않는다.

## 상태와 개입

상태 후보: 조사 중, 상대 응답 대기, 승인 대기, 오프라인, 중단 요청 중, 중단 확인, 복구 확인 필요, 사람 판단 필요, 완료.

- 정지 클릭 즉시 ‘정지 요청됨’을 표시하고 서버·connector·runtime 확인을 차례로 갱신한다.
- 네트워크가 끊기면 마지막 확인 시각과 중단 미확인 상태를 표시한다.
- 방향 변경의 중단 확인·새 turn 적용 상태를 표시한다. 후속 live steer를 도입하면 현재 turn 적용 여부를 별도로 표시한다.
- 같은 AI session을 기존 앱에서 사용 중이면 중복 실행 경고와 실제 연결 수준을 표시한다.
- UNKNOWN 실행은 ‘실패’ 버튼 하나로 자동 재시작하지 않는다. 찾은 실행 기록과 사용자 복구 선택을 보여준다.

## 조사 시작과 종료

시작 폼의 필수 항목은 문제, 기대 동작, 대상 환경, 연결할 두 AI, 공유 범위다. 해당하는 경우 상품/요청/명령 ID를 입력한다. 원인 가설은 선택 사항으로 두고 사실과 구분한다.

접속·기기·저장소·계정·session 준비 상태와 설정 화면은 [첫 사용 설정](onboarding-and-settings.md)을 따른다. 관찰만 하는 사용자는 연결 프로그램 없이 방을 볼 수 있고, 자기 AI 실행에는 명시적인 연결 준비가 필요하다.

종료 화면에는 원인 후보·확인한 근거·양쪽 저장소별 작업·미확인 사항·검증 계획을 보여준다. AI들은 결과 초안을 만들고 사람은 해결/추가 조사/보류를 선택한다.

## 첫 사용자 검증

두 개발자가 실제 공동 문제를 조사하는 화면을 함께 사용한다. 다음 항목을 관찰한다.

1. 개인 입력을 상대방에게 보내는 입력으로 오해하지 않는가.
2. 발신창의 미리보기를 확정 답변으로 오해하지 않는가.
3. 현재 기다리는 대상과 멈춘 이유를 바로 이해하는가.
4. 중단 요청과 중단 완료의 차이를 이해하는가.
5. 결론의 근거·가설·검증 여부를 구별하는가.
6. AI 대화량이 늘어 사람이 읽어야 할 부담이 더 커지지는 않는가.

접근성은 키보드 조작, 상태 텍스트, 초점 보존, 실시간 로그의 무분별한 스크린리더 낭독 방지, 한글 입력 중 제출 방지를 기본으로 검증한다.
