# 아키텍처 결정 기록

확정된 결정 중 변경 비용이 크고, 맥락 없이는 이유를 알기 어려우며, 대안 사이의 trade-off가 있었던 선택을 기록한다. 검토 중인 기술안과 대안은 [미결 선택](decisions-and-open-items.md#검토-중인-기술-선택)에 둔다. 문서 작성은 구현·구매·배포 승인을 뜻하지 않는다.

## ADR-001 — 초기 사용 범위를 개인·비상업용 실험으로 제한

**상태: 확정 (제품 범위, 2026-09-30)**

초기 사용은 두 사용자의 개인·비상업용 실험이다. 회사 업무용 운영이나 외부 고객 SaaS로 바로 확장하지 않는다. 이 경계는 무료 플랜 적격성, 데이터 정책, 계정·비용 가정을 바꾸므로 회사 사용으로 전환할 때 별도 결정을 요구한다. Vercel Hobby와 Supabase Free는 이 범위에서 검토하는 운영 가정일 뿐, 이 항목이 해당 기술 선택의 승인을 뜻하지 않는다. AI 구독/API 비용은 호스팅·DB 비용과 별도다.

## ADR-002 — 첫 구현의 언어와 중앙·로컬 경계

**상태: 채택 (승인된 단계별 구현, 2026-10-01)**

웹·짧은 제어 API는 Next.js/TypeScript, 로컬 connector는 Node.js 24/TypeScript, 사람 인증·관계형 정본은 Supabase Auth/Postgres로 구현한다. 조사 대상 저장소와 독립된 제품이며 두 코드 영역의 공개 계약을 대조한다. 초기 클라우드 배포 기준은 개인·비상업용 Vercel Hobby + Supabase Free지만 실제 계정 연결·배포는 아직 하지 않았다.

별도 언어/상시 서버는 운영 단위를 늘리고, 대상 서비스 안에 내장하는 방식은 업무 도메인·권한·배포에 제품을 결합한다. 현재 구조는 각 PC의 outbound 연결을 유지하고 웹 서버에 provider credential·로컬 root·원격 셸을 맡기지 않는다. durable 실행·Realtime·각 공급자 adapter는 단계 직전에 실제 결과를 반영해 구체화한다.

## ADR-003 — 사람 인증과 opaque 기기 scope의 분리

**상태: 채택 (기기 등록 구현, 2026-10-01)**

로컬 connector는 사람 cookie/JWT로 권한을 위임받지 않고 별도의 opaque credential로 고정 기기 RPC만 호출한다. 사람의 일회용 code 승인과 로컬 proof 보유를 함께 요구하며 DB에는 hash만 보관한다. 원문을 hash하는 공개 wrapper, live 소유자/조직/방/기기 재검사, 제한된 receipt 복구로 유실·취소·재초대의 경계를 유지한다.

사람 JWT 또는 중앙 admin key를 로컬에 주는 대안은 관리 API·tenant 접근 권한을 넓힌다. 대신 별도 기기 권한 경계와 로컬 private journal의 복구 부담을 감수한다. opaque credential을 Realtime JWT로 취급하지 않으며 push 인증은 별도 검증한다. 등록·heartbeat는 실제 AI readiness나 실행 종결의 증거가 아니다.

## ADR-004 — 중앙 실행 정본과 공급자 실행기를 별도로 검증

**상태: 채택 (실행 조정 구현, 2026-10-01)**

중앙 DB가 지정 질문·수신 run·답변·유일 후속 요청과 revision/epoch·예산·lease/fence를 소유한다. 로컬 실행기는 고정 device API를 소비하고 provider 세션·실행 의도·종결·업로드 대기를 별도 저널에 보관한다. 중앙의 start intent와 terminal 보고만으로 실제 provider 호출·종결을 입증하지 않으며 가짜 driver 검사와 실제 adapter 검사를 구분한다.

중앙 조정을 먼저 실제 Auth/DB/HTTP로 검증하면 공급자 이벤트 차이와 별개로 권한·중복·늦은 답변·UNKNOWN을 확인할 수 있다. 대신 두 정본 사이의 장애 복구와 로컬 outbox를 후속 통합에서 검증해야 한다. 사람 HttpOnly cookie와 opaque device scope를 유지하는 동안 웹 이력은 bounded polling/backfill로 복원하고, Realtime 알림 중계는 별도 인증·재접속 검증 후 추가한다.

## ADR-005 — 각 PC의 기존 에이전트 설정과 공동 정보 공개를 분리

**상태: 사용자 확정 (2026-10-01, 2026-10-02 권한 제한 보완; 구현 보정 중)**

각자의 기존 공식 CLI 로그인과 개인·프로젝트 지침, 스킬 및 관리 정책을 적용한다. 별도 프로필이나 자동 지침 제거를 기본으로 요구하지 않는다. 모델·effort는 웹에서 각 연결 소유자가 지원값을 선택하고 그 작업에 적용하며 개인 설정 파일은 바꾸지 않는다. 사용자가 확정한 공동 조사 범위는 읽기·격리 검증·수정 제안이다. 후속 선택에 따라 읽기 전용을 우선하고 권한을 검증하지 못한 MCP·플러그인·훅 실행은 조사 세션에서 제한한다. 설정 파일 보존이 모든 실행 기능의 무조건 활성화를 뜻하지 않는다. 원본 프로젝트 수정·커밋·배포를 승인하지 않는다. managed policy와 충돌하는 권한 상한은 우회하지 않고 준비를 거절한다. 개인 설정 원문·공급자 인증·내부 경로를 중앙에 복제하지 않고 방에 보낼 질문·답변·근거와 공유 별칭을 별도 검증한다. 사용자 대신 승인하지 않는다.

선택한 자료만 로드하는 격리 프로필은 입력 출처를 좁히지만 각자가 축적한 작업 규칙·도구·프로젝트 맥락을 제거하고 별도 로그인 부담을 만든다. 사용자는 기존 에이전트 설정 유지가 이 제품의 사용 목적에 더 맞다고 선택했다. 그에 따라 제품 파일 도구의 allowlist를 native/MCP 전체의 로컬 접근 제한으로 주장하지 않는다. 별도 개인 설명 대화를 공동 조사에 자동 병합하지 않는 경계는 유지한다. 실제 설정 보존·승인·공동 전송 검증은 진행 중이다.
