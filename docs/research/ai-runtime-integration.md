# AI 런타임과 기존 작업 맥락 연결

이 제품의 핵심 기술 검증 문서다. 공급자 사실의 확인일은 각 출처에 기록하며, 실제 사용 도구·버전·계정으로 다시 검증해야 한다. 웹·로컬 실행 경계, 각자 접속하는 순서와 로컬 확인 결과는 [로컬 AI 연결 조사](local-ai-connection-research.md)에 둔다.

## ‘내 AI’를 연결한다는 의미

자기 AI 연결은 답변용 AI를 제공하거나 AI 간 공동 조사에 참여할 때 필요하다. 상대 AI에 웹으로 질문하는 참가자는 자기 runtime·모델·로컬 경로를 연결하지 않아도 된다. 대상 연결 소유자의 설정과 실행·공유 범위는 그대로 적용한다. [직접 질문 규칙](../BUSINESS-LOGIC.md#사람이-상대-ai에-직접-질문하는-흐름)

| 수준 | 내용 | 보존하는 것 | 제약 |
|---|---|---|---|
| L0 새 세션 | 같은 저장소에 새 AI를 시작 | 현재 파일과 명시한 지침 | 기존 구현 의도·대화 맥락이 없다 |
| L1 선택 맥락 | 기존 AI가 만든 인계 요약·선택 자료를 새 세션에 전달 | 사용자가 선택한 작업 배경 | 요약은 원본 전체가 아니며 가정·생략을 확인해야 한다 |
| L2 저장 세션 | 기존 세션을 중단/종료한 뒤 공식 resume/fork로 연결 | 공급자가 저장한 대화·도구 기록 | 파일 상태와 실행 중 프로세스가 복원되는지는 별도 |
| L3 실시간 연결 | 이미 작업 중인 같은 런타임에 추가 클라이언트가 연결 | 동일 실행과 실시간 상태 | 호스트 앱의 공식 연결·소유권 API가 필요 |

화면에서 연결 수준과 맥락의 출처를 표시한다. L0/L1을 기존 세션 그대로 연결했다고 표현하지 않는다. L2 실패 시 사용자에게 알리지 않고 L0으로 바꾸지 않는다.

## 공식 자료로 확인한 기능

| 항목 | Codex app-server | Claude Agent SDK |
|---|---|---|
| 제품이 관리하는 로컬 실행 | 로컬 app-server 프로세스와 RPC | SDK가 CLI subprocess 관리 |
| 저장 세션 | resume·fork·read | resume·fork, transcript 보관 |
| 대화·도구 이벤트 | 메시지 delta·도구 활동·승인 요청 | 메시지·도구 stream; 하위 agent 표시는 기능별 차이 |
| 실행 중 입력 | `turn/steer`, 해당 active turn 확인 필요 | 입력 큐와 interrupt 후 후속 query를 기준으로 설계 |
| 실행 중 중단 | `turn/interrupt` | persistent streaming 실행에서 interrupt |
| 다른 앱의 독립 실행 세션 | 임의 CLI/IDE 프로세스 live attach 보장으로 해석할 수 없음 | 기존 별도 CLI 프로세스에 붙는 공식 API로 해석할 수 없음 |

근거: [Codex app-server](sources.md#s3), [Claude 세션·실행](sources.md#s5), [Claude streaming·중단](sources.md#s6). 인터페이스와 문서가 존재한다는 사실과 현재 팀 앱에서 직접 연동된다는 사실은 다르다.

Codex에는 동일 app-server에 접속하는 remote TUI·Unix socket·daemon/proxy 경로도 있고 Claude에는 공급자 웹/모바일을 연결하는 Remote Control이 있다. 이 기능들의 존재와 임의의 기존 앱 session을 우리 웹에서 제어할 수 있다는 보장은 다르다. 현재 앱과 동일 host를 공유할 수 있는지, 제3자 client 인터페이스·동시 입력·승인이 어떻게 동작하는지는 [공식 원격 기능과 후속 실험](local-ai-connection-research.md#구현-전에-닫을-실험)을 따른다. [근거](sources.md#s13)

Codex app-server는 로컬 child process와 stdio 연결을 우선 후보로 삼는다. runtime 자체의 TCP WebSocket 공개를 공동 통신 구조로 쓰지 않는다. 공동 조사 서비스와의 통신은 별도 connector가 수행한다.

Claude transcript는 대화 기록이며 파일시스템 snapshot이 아니다. PC를 옮기거나 다른 cwd에서 이어갈 때 기록 이동만으로 저장소·설치 도구·프로세스 상태까지 복원되지 않는다. [세션 저장 근거](sources.md#s5)

## 구현 접근 비교

| 접근 | 장점 | 포기하거나 검증해야 할 것 |
|---|---|---|
| 제품이 런타임 소유 | 입력·이벤트·중단·승인을 일관되게 제어 | 기존 앱 사용 경험과 맥락 이전 부담 |
| 기존 AI에 MCP 통신 도구 추가 | 자기 AI가 질문·답변을 보내는 흐름을 유지 | MCP 도구만으로 외부 메시지가 실행 중 세션에 자동 주입되거나 AI가 깨어나는 것은 아님 |
| 기존 앱의 공식 plugin/bridge | 현재 화면·세션 경험 보존 가능 | 앱별 API·동작·버전·권한·배포 유지 부담 |
| 터미널 화면 복사/키 입력 자동화 | 일부 도구의 시연이 쉬울 수 있음 | 구조화된 상태·승인·중단 판정 불안정; 제품 기반으로 권고하지 않음 |

**권고:** 먼저 실제 팀 도구를 대상으로 L2/L3 가능성을 실험한다. L3가 확인되지 않으면 connector 소유 세션과 L1/L2 인계로 첫 수직 구현을 만든다. 이 방식의 전환 비용이 제품 가치보다 크면 기존 앱 도구 연결부터 범위를 좁힌다.

## 공급자 차이를 숨기는 연동 표면

```typescript
type RuntimeCapabilities = {
  resume: boolean;
  fork: boolean;
  liveSteer: boolean;
  interrupt: boolean;
  toolEvents: boolean;
  approvalEvents: boolean;
};

// Conceptual contract; not an implemented SDK wrapper.
interface AgentRuntime {
  open(input: OpenSessionInput): Promise<SessionRef>;
  run(input: RunInput): Promise<RunRef>;
  observe(run: RunRef): AsyncIterable<RuntimeEvent>;
  intervene(input: InterventionInput): Promise<InterventionReceipt>;
}
```

권한·cwd·소유자·문맥 출처·공유 범위는 `OpenSessionInput`과 로컬 정책에 포함한다. TypeScript 선언만으로 실제 호환성을 입증하지 않으며 타입·에러·순서·종결 조건까지 구현 계약으로 정해야 한다.

지원하지 않는 `liveSteer`를 일반 메시지 전송으로 성공 처리하지 않는다. MVP의 방향 수정은 interrupt 후 새 epoch의 새 turn으로 통일하며, 지원되는 live steer도 첫 버전에서 비활성화한다. 기능 확대 시 runtime별 적용 위치·완료 경합을 검증한다. runtime별 approval event의 의미와 도구 중단 가능 범위도 검증한다.

### Claude native 상태 정보와 실행 증거

[009의 공식 CLI 관찰](../impl-spec/009-claude-code-runtime-compatibility.md#review-notes)에서 `command_lifecycle`은 입력 명령의 상태 정보다. `command_uuid`는 보낸 입력 UUID이고 `queued`, `started`, `completed`, `cancelled`, `discarded`, `refused`를 사용한다. 같은 예약 session과 입력의 정보만 읽고 원문 대신 hash를 기록한다. 이 이벤트로 도구 권한을 열거나 입력 ACK·typed 종결을 확정하지 않는다. `completed`나 `cancelled`라는 이름만으로 다음 입력을 만들지 않는다.

예약한 native UUID의 이력 파일 생성과 같은 입력 UUID·본문 hash의 사용자 기록은 저장 사실이다. 초기화가 보고한 ID·cwd, 입력 echo ACK, assistant tool-use, MCP dispatch, typed result는 각각 별도 증거다. 파일이 생성되어도 실제 답변·재개·중단을 확인하지 못하면 실행을 `UNKNOWN`으로 보존한다. 현재 판정과 다음 실제 검사 조건은 [진행 상태](../planning/delivery-and-validation.md#현재-진행-상태)를 따른다.

009의 private 검증 드라이버는 같은 활성 입력의 `system/thinking_tokens`를 진행 상태 정보로만 읽고 개수와 마지막 값만 유지한다. 거절한 상태 정보는 제한된 private 원문에 남기며 ACK·도구 권한·완료 증거로 사용하지 않는다. `control_cancel_request`도 host가 이미 중단을 요청한 소유 파일 callback의 취소 정보만 해석한다. 그 정보로 tool response를 만들거나 종결을 확정하지 않으며 interrupt receipt와 native typed 종결을 별도로 요구한다. 합성 실행의 통과는 공식 Claude의 실제 실행·이력 재개나 제품 연동의 완료를 뜻하지 않는다.

## 참가자별 도구·모델·effort 선택

2026-10-01 사용자가 추가한 제품 요구사항이다. 각 PC의 소유자가 AI binding별로 `Codex` 또는 `Claude Code`, 모델, effort를 선택한다. A의 설정과 B의 설정은 독립적이며 웹 로그인·방 역할·기기 credential은 모델 사용 권한을 대신하지 않는다. 현재 Codex 실험과 기기 등록 작업은 두 공급자의 선택 UI·실제 실행 지원을 입증하지 않는다.

추천 흐름은 로컬 connector가 설치·지원 버전과 모델 capability를 확인 → 웹의 내 연결에서 지원 조합 선택 → 로컬에서 인증·설정 적용 확인 → 준비 상태 표시다. 첫 사용의 기본값은 해당 runtime/model이 보고한 기본값으로 두고 사용자가 저장한 선택을 유지한다. `high` 등 같은 이름을 공급자·모델 간 동일한 추론량·비용으로 환산하지 않는다.

자기 AI를 연결한 참가자는 웹 채팅방에 들어올 때 자기 연결의 AI·모델·effort를 확인하거나 변경한다. 질문만 하는 참가자는 대상 연결만 선택한다. 재입장은 마지막 선택을 사용하며 매번 다시 선택하도록 강제하지 않는다. 참가자 카드와 질문 입력에는 사람·AI·공유 프로젝트명·작업 영역 별칭을 표시하고 메시지에는 질문 당시 대상 연결을 남긴다. 표시명 변경으로 과거 질문의 대상이 바뀌지 않으며 라우팅 권한은 표시명이 아닌 서버 binding/epoch로 판정한다.

- Codex 공식 app-server는 `model/list`의 모델별 `supportedReasoningEfforts`·`defaultReasoningEffort`를 제공하고 `turn/start`에 `model`·`effort`를 지정한다. 반환 목록을 선택 후보로 사용하며 목록 존재만으로 계정의 실제 실행 권한을 확정하지 않는다. [공식 근거](sources.md#s18)
- Claude Code는 모델·effort를 지정할 수 있고 모델/조직 정책에 따라 적용값이 바뀔 수 있다. 공식 Agent SDK 0.3.286의 공개 타입에서 `supportedModels()`의 optional capability, 시작 옵션 `model`·`effort`, 세션 전용 설정 변경과 조건부 hook의 effort 관찰값을 확인했다. setter 성공만으로 적용을 확정하지 않으며 선택한 버전에서 실제 실행을 검증한다. [공식 근거](sources.md#s18)

웹에는 공유를 확인한 도구·모델·effort·설정 상태만 전달한다. provider 인증, 로컬 실행 파일/계정 profile 경로, native session locator는 로컬에 둔다. runtime/모델 capability를 공용 API에 반영할 때도 명시적인 공개 DTO만 사용한다. 서버가 임의 실행 명령이나 개인 설정 파일 내용을 배포하지 않는다.

설정 변경은 해당 binding 소유자만 요청한다. active run 중에는 즉시 덮어쓰지 않고 종결 확인 뒤 다음 turn부터 적용한다. provider·session을 교체하거나 실행 문맥을 바꾸면 새 bindingEpoch와 맥락 확인을 사용한다. 이미 claim한 요청은 승인 당시 설정을 고정하고 오래된 설정의 continuation을 새 문맥에서 자동 실행하지 않는다. UNKNOWN인 실행은 설정 변경만으로 재호출하지 않는다.

지원 밖 조합·계정 접근 거절·조직의 clamp·model alias 변경을 조용히 성공으로 처리하지 않는다. 요청한 설정과 관찰한 적용값을 따로 기록하고 불일치를 알린다. runtime이 실제 effort를 확인할 수 없으면 미확인으로 남긴다. 다른 모델·effort·provider로의 전환은 사용자 확인 후 진행하며 개인의 기존 도구 기본 설정을 수정하지 않는다.

후속 수용 검사는 두 binding의 서로 다른 선택 유지, 모델별 effort 범위, 요청/적용 불일치, 재시작·resume 후 설정 보존, active/UNKNOWN 변경 차단, 권한 취소와 설정 경쟁, Codex↔Claude의 실제 질문 왕복을 포함한다. 인증·과금 경로는 [공급자 인증 경계](#인증과-비용--우선-확인할-제약)를 그대로 적용한다.

007의 로컬 Codex 구현은 binding별 요청 설정과 owned context를 별도 private 저널에 저장한다. 지원 목록·명시적 선택을 확인하고 thread start/resume와 turn start에 model/effort를 각각 지정한다. 요청값, thread가 보고한 값, turn model/reroute, turn effort 미확인을 구분한다. 웹의 공개 설정 DTO와 Claude adapter는 이어 구현하며 실제 수용 완료 전까지 두 공급자 연결을 지원 완료로 표시하지 않는다. ## 기존 개인 에이전트 설정 유지

2026-10-01 사용자는 각 PC의 기존 에이전트 설정을 적용하는 방식으로 진행하도록 확정했다. Codex와 Claude Code가 자기 PC의 전역·프로젝트 지침, 스킬 및 관리 정책을 공식 로딩 규칙에 따라 사용한다. 2026-10-02 후속 선택은 읽기 전용 우선이며 권한을 검증하지 못한 MCP·플러그인·훅 실행을 공동 조사 동안 제한한다. connector는 설정·auth 파일을 수정하거나 복사하지 않고 모델·effort·작업 cwd·제품의 협업 도구와 작업 권한 상한을 해당 실행에 적용한다. 기존 로그인과 설정을 분리하는 전용 프로필을 필수로 요구하지 않는다.

로컬 AI가 참고하는 맥락과 방에 전송하는 정보는 별개의 경계다. 개인 지침은 로컬 AI의 입력이 될 수 있으며 그 존재만으로 준비를 거절하지 않는다. 방에는 확인한 공개 별칭, 질문·답변·근거 및 실행 상태를 전달한다. 설정 원문·인증 정보·내부 session ID와 절대 경로를 그대로 올리지 않으며, 개인 설명 세션의 대화를 공동 입력에 자동 병합하지 않는다. 사용자 설정으로 활성화한 native/MCP 도구의 로컬 접근까지 선택 파일 도구가 격리한다고 주장하지 않는다. 공동 실행의 작업 목적과 제품이 요청하는 실행 범위는 유지하고 기존 승인 규칙을 우회하거나 자동 승인하지 않는다.

공유 범위 확인은 권한 있는 해당 방·조사 목적·선택 근거에 관한 AI 생성 결론의 사전 공유 동의다. 자동 질문은 별도 동의를 받아 지정 상대에게 전송한다. 개인 설정이 생성 내용에 영향을 줄 수 있지만 개인 지침·훅·설정 원문 공개나 파일 수정 권한으로 확대되지 않는다. 공동 조사에 추가할 협업 입력은 질문·final 양쪽에 설정 원문·인증정보·내부 식별자·출처 경로의 재출력을 금지한다. 제품 DTO에는 원시 설정·provider 응답을 복사하지 않고 알려진 민감값과 미확정 출력을 보류한다. 확정 답변 이벤트는 문구 전체의 출처를 증명하지 않으며 모르는 개인 평문까지 검사한다고 보장하지 않는다.

개인 설명 이력의 분리는 제품이 관리하는 설명 transcript·session ID·인계를 공동 owned 세션에 자동 import/resume/fork하지 않는 경계다. 공급자의 기존 전역 선호·memory에 과거 개인 정보가 전혀 없다는 의미가 아니다. 개인 설명 기능 자체는 후속 구현 범위로 남아 있다. 사용자는 공동 조사를 읽기·격리 검증·수정 제안으로 확정했다. 개인 설정은 유지하며 조사 세션에는 읽기 전용 실행 권한을 적용한다. 원본 프로젝트 수정·커밋·배포는 하지 않으며 개인 설정이나 상대 질문으로 수정 승인을 추정하지 않는다. 격리 검증 환경의 쓰기 경계를 확인할 수 없으면 실행 대신 검증 방법을 제안한다. 공급자별 적용과 실제 확인 범위는 [진행 상태](../planning/delivery-and-validation.md#현재-진행-상태)를 따른다.

Claude 일반 `-p`는 `--bare` 없이 개인·프로젝트 맥락을 로드하는 공식 경로다. 기존 로그인·지침을 유지하며 실행 기능의 권한 제한을 별도로 검증한다. 공식 문서의 동작과 각 설치 버전에서 관찰한 적용 범위는 구분하며 상세 근거는 [S23](sources.md#s23)에 둔다. Codex의 007은 개인 지침·설정 파일 보존과 작업 전용 실행 제한을 함께 적용한다. 실제 확인 범위는 공급자별 코드·실행 증거·독립 리뷰를 기준으로 기록한다.

## 세션 소유와 맥락 인계

- `deviceId`, `workspaceBindingId`, `agentBindingId`, `runtimeSessionId`, `runtimeTurnId`, 저장소 snapshot을 분리한다.
- 로컬 root와 session cwd를 검증한 등록 연결을 조사방에서 선택한다. 웹 로그인만으로 대상 session을 추측하지 않는다.
- 한 runtime session은 한 connector가 소유하고 active turn은 최대 하나다.
- 기존 CLI/앱이 같은 세션을 실행 중이면 동시 resume를 막거나 공식 공유 호스트 방식으로 연결한다. 저장 파일이 있다는 사실만으로 동시 실행을 허용하지 않는다.
- 맥락 패키지는 목표, 최근 결정, 관련 경로, 미완료 작업, 가정, 금지된 작업, snapshot 식별자와 생성 출처를 담는다.
- 원본 대화 전체·숨은 모델 상태·개인 메모리가 자동으로 공유되는 것으로 가정하지 않는다.
- 공급자 native session locator와 absolute path는 로컬 매핑에 두고 웹에는 opaque binding ID와 선택한 별칭만 제공한다.
- 상대 AI는 전달된 근거를 받은 것이며 상대 저장소를 직접 읽었다고 표시하지 않는다.

## 로컬 실행 기록 보관과 용량

연결기는 완료 답변을 저장한 뒤 서버 전송이 막히지 않도록 주 실행 기록의 공간을 따로 확보한다. 주 JSON 파일은 2MiB, 작업은 1,024개, 시도와 전체 소유 턴은 각각 256개로 제한한다. 새 실행 전에는 시도·소유 턴·직렬화 바이트와 미확정 응답 공간을 확인한다. 부족하면 `RUNTIME_CAPACITY`로 실행을 거절하고 준비 상태를 false로 유지한다. 자동으로 예산·이력·세션을 초기화하지 않는다.

완료 전송이 확정된 요청 묶음만 원문을 보존해 별도 파일로 옮긴다. 같은 요청의 모든 시도는 업로드 완료 또는 실행하지 않았다는 증명이 있어야 하며, 연결된 작업도 확정 또는 적법한 종료 상태여야 한다. 미확인 `UNKNOWN`, 전송 전 `TERMINAL`, 미확정 상대 질문은 주 파일에 남는다. 공급자 세션의 전체 소유 턴은 보관 후에도 그대로 유지한다.

보관 파일은 보관 직전 주 JSON 원문이며 내용 해시로만 이름을 정한다. 파일 0600·디렉터리 0700, 소유 UID, 실제 경로, 링크 수, 해시·schema·연결 범위·이전 참조 순서를 확인한다. 보관 참조는 최대 64개, 요청 ID는 합계 4,096개, 참조 원문은 합계 128MiB다. 먼저 보관 파일과 디렉터리를 내구 저장하고 마지막에 주 파일의 참조를 교체한다. 주 파일에 연결되지 않은 잔여 파일은 완료 근거로 채택하지 않는다.

정상 선택 파일 읽기는 정확한 경로·인자와 정수 크기 0…65,536바이트가 확인된 snapshot에 한해 최악의 JSON 저장 비용 `6 * size + 4096`을 예약한다. 빈 파일도 포함하고 최대 파일의 기존 예약량은 유지한다. 미선택 경로·별칭 경로·잘못된 인자·비정상 크기는 기존 최대 예약을 유지하며, 예약 뒤 인증·파일 identity·내용 변경 검증과 결과 저장을 그대로 수행한다.

응답 저장과 시도 snapshot 저장은 각각 남은 공간을 계산한다. 이미 저장한 응답을 예약에서 다시 더하지 않으며, 실제 commit이 확인되기 전에 공용 예약을 줄이지 않는다. 재시작에서 큰 종결 결과가 남으면 같은 완료 전송 작업의 ID·본문으로 회복한 뒤 기존 준비·질문 작업을 처리한다. 새 공급자 실행으로 전송을 우회하지 않는다.

마지막 완료 요청을 보관한 뒤에는 검증된 원문에서 상태·종결·서버 확정을 표시한다. 새 claim이 유효하게 저장된 이후에만 새 시도를 표시한다. 명시적 로컬 연결 제거는 기존 미해결 상태 검사와 주 파일 제거를 유지하며 보관 원문을 자동 삭제하거나 새 연결에 채택하지 않는다. 일반 저장은 보관 파일을 한 번 읽고 해석한 결과로 이전·다음 관계를 따로 확인한다. 검증 범위 전후의 열린 파일·현재 경로·디렉터리 확인이 끝나야 주 파일을 교체하며 모든 handle의 종료를 시도한다. 결과는 한 저장을 넘겨 보관하지 않는다. 보관 읽기 비용은 현재 원문 합계에 비례한다. 구현의 수용 상태와 성능 측정·후속 최적화는 [진행 정본](../planning/delivery-and-validation.md#현재-진행-상태)에 기록한다.

## 개인 설명 세션

개인 설명은 공개 조사 session의 입력으로 넣지 않는다. 별도 세션에 사용자가 선택한 공동 메시지와 읽기 전용 snapshot을 전달한다. 지원되는 공식 fork를 쓸 때도 조사 세션과 다른 실행 ID·권한을 사용한다.

설명 세션은 파일 수정·상대 AI 질문·공동 방향 변경 권한이 없다. 개인 대화 내용을 공유하려면 사용자가 문구를 선택하고 공개 전환을 승인한다. 공동 조사의 방향을 바꾸는 요청은 개인 설명과 별도의 intervention이다.

개인 설명의 호출 수도 자기 사용자 한도로 제한하고 비용을 표시한다. 공개 조사 사이클과 분리된 개인 사용 내역을 공동 참여자에게 자동 공개하지 않는다.

## 인증과 비용 — 우선 확인할 제약

- Codex의 기존 CLI 로그인과 제품에서 OAuth 토큰을 취급하는 통합은 구분한다. 제품이 공급자 token 파일을 복사하거나 중앙 서버로 올리지 않는다.
- OpenAI의 공식 SIWC 구독 사용 경로는 공개된 적용 범위·사용자 동의·배포 형태 제약이 있다. Vercel 웹을 포함한 이 제품 형태가 해당 범위에 들어가는지 확인해야 한다. 구독이 일반 hosted API 사용 권한이라고 가정하지 않는다. [공식 근거](sources.md#s4)
- Claude는 사용자의 2026-10-01 선택에 따라 기존 구독 로그인을 우선 검토한다. 후보는 각 사용자가 공식 비변조 Claude Code에 직접 로그인하고 각 PC의 connector가 그 CLI를 실행하는 구조다. 공식 제품 실행 조건에는 Commercial Terms 동의, 내장 인증 유지, 사용자별 직접 인증·과금과 사용량 대납·재판매·중개 금지가 포함된다. 공식 문서는 비변조 CLI의 사용자 직접 구독 로그인을 명시적으로 구별한다. [공식 근거](sources.md#s20)
- Claude의 제품 자체 로그인 제공·구독 credential 수집/저장/중개 제한과 SDK 개인 사용의 과금 안내를 함께 적용한다. 웹은 제품의 공동 문구·상태를 전달하고 공급자 인증은 공식 CLI가 소유한다. 이 구조가 구독 요청 중개 제한에 해당하지 않는다는 판단은 별도 적격성 검증이며, 공식 문서나 실제 계정 실행으로 확인한 결과와 구분한다. `claude -p`도 CLI를 통한 SDK 실행으로 설명되므로 API/package 선택만으로 제한이 사라진다고 해석하지 않는다. 구독 로그인을 사용하지 않는 `--bare`는 기존 로그인 후보와 호환되지 않는다. API/provider 인증은 대안으로 유지한다. [공식 근거](sources.md#s20)
- 회사 API 과금과 개인 구독을 혼합한다면 어느 호출이 어느 계정을 사용하는지 명확히 표시한다. 별도 설명 대화도 호출·비용이 발생할 수 있다.
- 공급자가 허용한 사용자 API 계정으로 구성할 수 있는지 검토하고, 구독 사용은 허용 범위를 확인한 뒤 선택한다. 개인·비상업용 Vercel/Supabase 무료 운영이 AI 사용 권한이나 무료 호출을 제공하지는 않는다. 요율·모델·한도는 확정 시점의 공식 자료를 사용한다.

## 실제 실험으로 닫을 항목

1. 팀이 쓰는 Orca/Codex/Claude/Cursor 등 정확한 앱과 버전, 공식 연결 API.
2. 저장 세션 resume/fork 후 어떤 문맥과 지침·도구 설정이 유지되는가.
3. 다른 앱에서 실행 중인 세션에 접근하면 동일 실행을 관찰하는가, 저장 기록만 다시 여는가.
4. 두 클라이언트의 동시 입력·소유권 경합을 런타임이 어떻게 처리하는가.
5. 중단 시 이미 실행 중인 도구·자식 프로세스가 언제 끝나며 무슨 작업을 완료했는가.
6. 출력·하위 agent·승인·토큰 사용 이벤트가 실제로 어느 범위까지 제공되는가.
7. 로그인·갱신·계정 변경·세션 복구, 공급자별 제품 통합 허용 범위.
8. 개인 설명 분기 이후 공개 session에 비공개 지시나 데이터가 섞이지 않는가.
