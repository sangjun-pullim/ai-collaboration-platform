# 제품 요구사항

상태: 제품 검토용 제안. 확정 요구는 사람의 상대 AI 질문·응답, 저장소별 AI 간 질문·응답, 웹 공동 관찰, AI 발신 과정 표시, 개인 설명과 방향 수정이다. 질문자의 AI·로컬 경로 연결은 선택 사항이다. 첫 버전 범위·기술 선택·개발 순서는 권고안이며 구현 승인을 뜻하지 않는다.

## Problem / Users

개발자들이 서로 다른 저장소를 담당하면서 공동 문제를 조사하거나 변경 영향을 확인해야 한다. 각 저장소의 코드·작업 맥락이 분리되어 있어 한쪽의 AI만으로 필요한 근거를 모두 확인하기 어렵다.

각자의 AI는 코드와 최근 작업을 조사할 수 있지만 상대 AI에게 질문하려면 사람이 내용을 해석하고 전달해야 한다. 추가 질문마다 이 왕복이 반복된다. 구현 속도에 비해 사람의 이해와 설명이 따라가지 못하면, 관측 사실·설계 의도·추정이 섞이고 공동 문제를 좁히는 데 시간이 든다.

제품은 특정 업무 도메인이나 서비스 조합에 종속되지 않는 저장소 간 AI 협업 도구다. 첫 검증 사용자는 사용자 본인과 협업 개발자다. 사람 두 명과 답변용 AI 하나로 질문·응답을 시작할 수 있고, 양쪽 AI를 연결하면 공동 조사로 확장한다. 이후 다른 저장소 담당자, 리뷰어, 운영 담당자로 확장할 수 있다. AI는 참가자의 도구이며 사용자와 같은 실행 권한 주체로 취급하지 않는다.

사용자는 초기 사용을 개인·비상업용으로 확인했다. 첫 실험은 Vercel Hobby + Supabase Free의 무료 한도를 기준으로 한다. 앞서 언급한 회사 내부 활용은 향후 확장 가능성이며 현재 사용 전제로 삼지 않는다. AI 구독/API 비용은 호스팅 무료 여부와 별도로 확인한다.

## Goal

- 개발자는 자기 AI나 저장소를 연결하지 않고도 웹에서 원하는 상대 AI에 질문하고 코드 근거가 붙은 답변을 받는다.
- 각 AI가 자기 저장소를 조사하고 상대 AI에게 구체적인 질문을 전달한다.
- 개발자는 같은 공동 기록을 보면서 현재 조사 상태와 근거를 이해한다.
- 개발자는 자기 AI에게 개인 설명을 요청하고, 조사 방향을 바꾸고, 공동 조사를 중단·재개한다.
- 결과에는 확인된 사실, 미확인 가정, 저장소별 수정 제안, 담당자, 양쪽을 연결하는 검증 시나리오가 남는다.
- 저장소 사이의 공동 문제를 조사하는 데 드는 사람의 중계 시간과 누락을 줄인다.

## Scope

### 범용 조사 대상

답변할 참가자가 저장소와 지원 AI를 연결하면 다른 참가자는 그 AI에 질문할 수 있다. 양쪽 AI를 연결하고 조사 목표를 정하면 AI 간 공동 조사도 사용한다. API 연동, 프런트엔드·백엔드 계약, 공통 라이브러리 변경 영향 등은 적용 사례다. 특정 서비스의 업무 데이터나 판매·관리 기능을 제품 사용의 필수 조건으로 두지 않는다. 첫 파일럿 사례는 [개발·검증 순서](delivery-and-validation.md#3-작은-파일럿)에 따로 둔다.

### 공동 조사방

문제 하나를 조사방 하나로 다룬다. 목표·증상·기대 동작·대상 환경·식별자를 기록하고 사람과 AI 참가자를 연결한다. 질문·답변·근거·공동 결정·조사 상태를 보관한다.

사람이 상대 AI에 질문하는 단방향 흐름과 두 AI가 질문을 주고받는 공동 조사 흐름을 지원한다. 단방향 질문자는 웹 로그인과 방의 질문 권한만 필요하며 자기 AI·기기·로컬 경로를 등록하지 않아도 된다. 질문한 상대 AI만 실행하고 답변을 같은 질문에 연결한다. 질문자 AI나 AI 간 후속 왕복을 자동으로 실행하지 않는다.

동료 여러 명의 참여도 확정 요구에 포함한다. 1:1 방에서는 상대 연결을 기본 질문 대상으로 지정한다. 여러 명이 참여하는 방에서는 질문할 참가자와 그 참가자의 저장소 연결을 선택한다. 질문 당시의 대상을 기록하고 이후 연결 변경으로 대상을 바꾸지 않는다. 첫 검증은 웹에서의 단방향 질문·답변부터 진행하고 두 AI의 공동 왕복을 별도로 확인한다. 다자 방의 대상 선택은 첫 질문·답변 검증 이후 별도 구현 단계로 다룬다.

### 로컬 AI 연결

자기 AI를 답변이나 공동 조사에 제공할 참가자만 로컬 연결 프로그램을 설치하고 자기 저장소와 AI 런타임을 선택한다. 질문만 하는 참가자에게 설치·경로·AI 선택을 요구하지 않는다. 제품은 연결 수준을 명시한다: 새 세션, 선택한 맥락 가져오기, 저장 세션 이어가기, 실행 중 세션에 연결.

답변용 연결은 소유자가 방·저장소·실행·공유 범위를 확인하고 로컬 연결 프로그램을 실행해 둔다. 이 범위 안에서는 소유자가 매 질문을 직접 입력하지 않아도 AI가 답변한다. 웹 접속만으로 로컬 AI가 준비됐다고 판단하지 않으며 오프라인·권한 상실·준비 미확인일 때 새 AI 실행을 차단한다.

각 참가자는 공급자가 허용한 자기 계정·인증·과금 경로로 자기 AI를 연결한다. 제품의 웹 로그인·기기 연결과 AI 공급자 인증을 구분하고, 상대방에게 공급자 키나 로그인 토큰을 전달하지 않는다. 기존 구독을 이 제품에서 사용할 수 있는지는 별도 검증 대상이다.

AI 연결 소유자는 자기 연결별로 Codex 또는 Claude Code, 모델, 해당 모델이 지원하는 effort를 선택할 수 있어야 한다. 질문만 하는 참가자는 자신의 도구·모델·effort를 선택하지 않는다. 한 방에서 서로 다른 도구·모델·effort를 사용하며, 방 소유자가 다른 참가자의 실행 설정을 대신 바꾸지 않는다. 사용 가능한 선택지는 각 PC의 도구 버전·계정·정책으로 확인하고, 요청한 설정과 실제 적용된 설정을 구분한다.

참여 개발자는 주로 macOS와 Claude Code를 사용한다. Claude Code를 필수 지원 대상으로 두고 Claude↔Claude와 Codex↔Claude를 실제 왕복 검증에 포함한다. 웹 모델·effort 설정 확장에 앞서 각 PC의 기본 설정을 사용하는 Claude 연결을 검증한다. Windows·Linux 지원 범위는 후속 단계에서 정한다.

각 PC의 기존 공식 에이전트 로그인과 개인·프로젝트 설정을 기본으로 사용한다. 전역 지침, 프로젝트 지침, 훅, 스킬, 도구와 기존 권한·승인 규칙을 플랫폼 접속 때문에 제거하거나 전용 프로필로 분리하지 않는다. 웹에서 선택한 모델·effort는 해당 연결의 작업에 적용하고 개인 기본 설정 파일은 바꾸지 않는다. 개인 설정의 원문과 인증 정보를 방에 자동으로 공유하지 않는다. 이 정책은 2026-10-01 사용자가 명시적으로 확정했다.

공동 조사에서는 읽기·격리 검증·수정 제안까지만 허용한다. 개인 설정 파일과 지침은 유지하되 권한을 검증하지 못한 MCP·플러그인·훅의 실행은 해당 공동 조사 동안 제한한다. 이는 사용자가 추가로 확정한 실행 범위다.

웹 채팅방에서 질문 대상을 확인·선택한다. 자기 AI를 연결한 경우에는 지원 모델·effort도 확인·선택한다. 처음에는 로컬 기본값을 제안하고 재입장 때는 마지막 선택을 유지한다. 참가자와 질문 대상에는 사람 이름, AI 종류, 공유용 프로젝트 표시명과 작업 영역 별칭을 보여준다. 필요한 상대 경로는 소유자가 공유를 확인할 때만 추가하며 절대 경로는 자동 공개하지 않는다. 메시지는 질문 당시의 대상 연결·프로젝트를 기록하여 이후 연결 변경과 구분한다.

구현은 이미 실험한 connector 소유 Codex 경로부터 연결하고 Claude adapter를 같은 실행 계약에 추가한다. 모델 목록이나 effort를 제품 전체의 고정값으로 두지 않는다. 공급자·session 변경은 맥락 인계를 확인하며 새 세션을 기존 작업 AI와 동일한 맥락이라고 표시하지 않는다. 구체적인 적용·변경 규칙은 [참가자별 실행 설정](ai-runtime-integration.md#참가자별-도구모델effort-선택)을 따른다. 이는 구현할 요구사항이며 두 공급자의 제품 연동 완료를 뜻하지 않는다.

### 실시간 관찰과 개입

공동 대화창, 내 AI의 발신·작업 상태, 개발자 입력을 분리한다. 작성 중 문자열과 확정 메시지를 구분하고, 공개 가능한 도구 활동과 결과를 보여준다.

개인 설명, 자기 AI 방향 수정, 공동 발언, 자기 AI 중단, 방 전체 일시정지는 서로 다른 동작이다. 요청·전달·적용·종료 상태를 구분한다.

### 결과와 다음 작업

결론을 근거와 함께 저장한다. 사실·가설·제안·실제 검증 결과를 구분한다. AI 간 동의만으로 해결됐다고 표시하지 않는다. 각 저장소의 담당자가 제안을 확인하고 후속 구현 책임을 정한다.

### 접근과 정보 공유

초대된 사용자가 웹에서 접속한다. 방 참여 권한과 로컬 실행 권한을 별도로 관리한다. 자기 코드·발췌·로그를 공유할 범위는 해당 참가자가 정한다. 비공개 설명은 별도 문맥에서 처리한다.

## Non-goals

- 첫 버전에서 파일 수정·커밋·배포를 자동 수행하지 않는다: 공동 조사 효과와 실행 통제를 먼저 검증한다.
- 모든 IDE·AI 앱의 실행 중 세션을 즉시 지원하지 않는다: 공식 인터페이스와 호환성 실험이 필요하다.
- 상대 PC를 원격 셸처럼 조작하지 않는다: 참가자의 로컬 권한을 유지한다.
- 모든 저장소·개인 AI 기록을 중앙에 복제하지 않는다: 문제에 필요한 맥락을 선택해 공유한다.
- AI 합의를 테스트·사람의 업무 판단을 대신하는 증명으로 사용하지 않는다: 검증되지 않은 동의와 같은 오류가 반복될 수 있다.
- 첫 버전에서 외부 고객 SaaS·마켓플레이스·고급 에이전트 팀 기능을 포함하지 않는다: [확정된 초기 실험 범위](ADR.md#adr-001--초기-사용-범위를-개인비상업용-실험으로-제한)에 따른다.

## Success criteria

### 기능 수용 기준

- 질문자가 자기 AI·기기·로컬 경로를 등록하지 않은 상태에서 다른 PC의 준비된 AI에 질문하고 코드 근거가 붙은 답변을 받는다. 대상 AI만 실행하며 답변 후 자동 AI 왕복을 만들지 않는다.
- 두 PC의 각 AI가 자기 저장소를 조사하고 실제 질문·답변 한 왕복을 완료한다.
- 특정 업무 전용 설정 없이 다른 도메인의 저장소 조합과 조사 목표로 새 조사방을 시작할 수 있다.
- 각자의 허용된 공급자 계정으로 호출되며, 상대방의 공급자 인증정보를 공유하지 않는다.
- 두 브라우저에서 같은 확정 대화와 상태를 확인한다.
- 개인 설명이 상대방에게 공개되거나 공동 AI 문맥에 자동 반영되지 않는다.
- 개발자의 방향 변경·중단 상태가 실제 런타임 결과와 일치한다.
- 재접속 후 대화와 미처리 요청을 복원하되 이미 시작한 AI 호출을 자동 중복 실행하지 않는다.
- 저장소 버전과 근거가 연결된 공동 조사 결과를 남긴다.
- 로그인·방 권한·로컬 실행 권한을 우회하는 메시지를 거절한다.

### 제품 가치 측정

현재 방식의 문제 해결 기록을 기준선으로 확보하고 유사한 문제에 대해 비교한다. 사람의 설명·중계 시간, 결론까지 시간, 추가 질문 수, 잘못 전달된 사실, 재조사·재작업, 비용, 개발자의 이해도를 측정한다.

측정 수치·목표치는 아직 확정하지 않는다. 한 문제의 빠른 해결만으로 일반적인 생산성 개선을 주장하지 않는다. [개발·검증 순서](delivery-and-validation.md)의 파일럿 평가를 따른다.
