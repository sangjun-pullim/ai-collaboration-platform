# 제품화 제약·보안·운영

아래는 현재 요구를 기준으로 식별한 제약 목록이다. 기술·환경·조직 정책 변경에 따라 추가될 수 있으며 모든 미래 위험을 열거했다고 주장하지 않는다. 실제 재현 결과가 아닌 설계 검토다.

## 제약 지도

| 영역 | 제약·실패 상황 | 설계 대응 / 확인할 것 |
|---|---|---|
| 연결 대상 | 웹 로그인만으로 저장소와 AI를 알 수 없음 | 로컬 저장소 등록 + runtime session 선택 + 방별 binding |
| 기존 세션 | 현재 앱에서 실행 중인 session에 임의 attach 불가할 수 있음 | 공식 앱 API 확인, L1/L2/L3 실험, 연결 수준 표시 |
| 작업 맥락 | 같은 폴더에 새 AI를 띄워도 기존 대화는 없음 | 인계 출처·범위 표시, 기존 session 지원 여부 검증 |
| 코드 변동 | AI 조사 중 개발자가 수정·switch·rebase | 시작/종료 snapshot, drift 표시, 재검증 전 현재 결론에 채택하지 않음 |
| 공급자 | steer·interrupt·tool/subagent event 기능 차이 | capability handshake, 기능별 UI와 통합 실험 |
| AI 정확성 | 둘이 같은 잘못된 가정을 공유 | 근거·가설 분리, 코드·재현·계약 검증, 사람 판단 |
| 과도한 대화 | 질문 반복·불필요한 동의·무한 왕복 | 수신자 라우팅, 왕복·시간·호출 한도, 사람 개입 |
| 동시 실행 | 같은 session을 여러 앱/connector에서 사용 | 소유권·per-session 실행 lock, 공식 live sharing 외 중복 실행 금지 |
| 전달 | 실시간 알림 누락·중복·순서 역전 | durable DB, room sequence, 요청 멱등 키, backfill |
| 호출 불확실 | AI 호출 직후 connector 장애 | UNKNOWN, 로컬 저널, runtime 기록 확인, 자동 재호출 금지 |
| 중단 | 네트워크 단절·도구가 중단 요청 후 계속 실행 | requested/ack/terminated 구분, epoch, 과거 side effect 표시 |
| 기기 | 절전·종료·VPN·회사 프록시·운영체제 차이 | heartbeat, outbound 통신, 복구 절차, 지원 환경 제한 |
| 웹 호스팅 | Vercel WS 수명·인스턴스 분리·베타 | 관리형 realtime 우선, 외부 상태, 재접속, 선택 재검토 |
| 데이터 | 저장소·로그·직원/고객 정보가 클라우드를 통과 | 공유 scope·정책·보관/삭제·공급자 적격성 확인 |
| 권한 | 상대 AI가 명령 실행·비밀 공개를 요구 | 원격 메시지는 자료/제안, 소유자 권한·로컬 정책으로 판단 |
| 개인 대화 | private 입력이 public context로 샘 | 별도 session·storage·RLS, 선택 공개, 테스트 |
| 배포 접근 | `vercel.app`을 사내망 주소로 오인 | 앱 인증·방 권한, 보호 설정 범위 확인 |
| 과금 | 구독과 API entitlement 혼동·token fan-out | 공급자 허용 범위 확인, 호출별 계정·사용량·추정 구분 |
| 운영 | 프로토콜/SDK 업데이트·세션 이력 호환성 | 버전 handshake, 지원 matrix, 복구·롤백·업데이트 정책 |
| 채택 | 별도 앱·세션으로 바꾸는 부담이 절감보다 큼 | 실제 기존 앱 연동 실험, 파일럿 가치 측정, 범위 축소 |

## 신뢰 경계와 권한

| 주체 | 허용 범위 | 권한이 되지 않는 것 |
|---|---|---|
| 로그인한 사람 | 참여 방 읽기·공동 발언, 자기 AI 입력, 명시적 제어 | 다른 참가자 PC의 실행 승인 |
| 방 소유자 | 초대·방 목표·재개·결과 관리 | 각 PC의 공급자 키·파일·셸 권한 |
| 로컬 기기/connector | 연결한 소유자·저장소·방 scope의 실행과 상태 보고 | 조직 관리자나 전체 방 접근 |
| AI | 허용 scope의 조사, 질문·답변·제안 | 사람의 승인·역할·권한 생성 |
| 중앙 서버 | 요청 검증·저장·라우팅·감사 | 원격 raw shell 실행이나 로컬 sandbox 우회 |

MVP는 읽기·조사·제안까지만 지원한다. ‘읽기 전용 AI’라는 프롬프트만으로 파일 쓰기·네트워크 접근이 금지되지는 않는다. 실제 runtime sandbox, 도구 노출, 경로 제한, 로컬 승인 정책으로 강제한다.

개인·프로젝트 지침과 기존 설정 파일은 유지한다. 사용자가 확정한 읽기 전용 우선에 따라 권한을 검증하지 못한 MCP·플러그인·훅 실행은 공동 조사에만 제한한다. 외부 도구의 read-only 표시는 임의 부작용이 없다는 증명이 아니며 실행 기능을 제한한 상태와 설정 파일 보존을 구분한다. 관리 정책과 제한이 충돌하면 우회하지 않고 준비를 거절한다.

Codex의 작업 전용 제한은 공식 설정 선행 검사, 실행 기능 제한과 고정 protocol 경계로 검증한다. admission 동안 개인·관리 설정이 안정적인 환경이 기준이며 독립 프로세스 사이 외부의 동시 정책 변경을 원자적으로 차단하는 것으로 표현하지 않는다. 시작 직후와 조사 입력 전에 정책 변화가 확인되면 실행을 거절한다.

테스트도 DB·네트워크·파일에 영향을 줄 수 있다. 실제 테스트 스크립트와 환경을 확인한 뒤 허용한다. 나중에 수정·커밋 기능을 추가하면 승인한 경로·작업·입력·유효기간을 구조화하고 기존 승인 범위 안의 재작업을 반복 승인 없이 처리할 수 있게 설계한다.

## Prompt injection과 출처

상대 AI·저장소 파일·로그·문서의 텍스트는 조사 자료다. 그 안에 있는 지시를 system/developer 권한으로 올리지 않는다. 사람이 웹에 입력한 정식 제어 명령은 별도 인증·필드·server event로 표현한다.

모델만으로 injection을 완전히 차단한다고 주장하지 않는다. 정책 밖 작업은 로컬 도구 단계에서도 거절하고, 명시적으로 허용한 경로·행위·공유 범위만 수행하게 한다. 새 권한이 필요한 요청은 소유자에게 이유와 구체적인 작업을 보여준다.

## 로컬 경로와 파일

- 실제 저장소 root는 로컬 사용자가 등록한 canonical path를 사용한다. symlink·worktree·하위 경로가 scope를 벗어나는지 검사한다.
- 웹에서 임의의 절대 경로를 입력했다고 자동 등록·열람하지 않는다.
- `.env`, 공급자 인증, SSH 키, credential store, 허용 밖 홈 디렉터리를 읽는 도구를 배제한다.
- 다른 저장소나 운영 환경을 조사해야 하면 scope 변경을 명시적으로 요청한다.
- 경로와 파일의 비밀 문자열을 모두 검출할 수 있다는 가정을 두지 않는다. 공유 최소화와 소유자 확인을 함께 사용한다.

## 정보 공개 정책

공동으로 공개되는 것: 확정 질문·답변, 선택한 코드 발췌, 공유 가능한 작업 이벤트, 검증 결과, 선택한 로그, 근거의 저장소·버전 식별자.

로컬/개인으로 유지하는 것: 공급자 인증, 전체 개인 대화·메모리, 절대 경로, 원본 비밀 로그, 공개하지 않은 지시·고객 정보. 개인 설명 데이터는 해당 사람만 조회할 수 있고 공동 요약의 입력에 자동 포함하지 않는다.

공유한 자료는 상대 AI 공급자로도 전달될 수 있다. 중앙 클라우드뿐 아니라 각 model/provider의 처리 경로를 데이터 흐름에 포함한다. 사내 정책, 허용 공급자, 지역·보관·계약 조건은 조직 담당자가 확인해야 한다. 온프레미스가 요구되면 호스팅·인증·AI 실행 경로를 다시 선택한다.

원본 tool 이벤트를 먼저 공개한 뒤 나중에 redact하는 방식은 피한다. 로컬에서 공개 가능한 필드를 선택하고 크기·비밀 제외를 적용한 뒤 전송한다. 공유 카드에는 삭제·가림이 적용됐음을 표시할 수 있지만 유출 방지의 완전한 보증으로 표현하지 않는다.

## 인증·Realtime·서버 키

Supabase를 선택하면 일반 사용자 토큰, 기기 scope token, 서버 관리자 credential을 구분한다. 서버의 secret/service-role 키를 브라우저나 배포되는 connector에 포함하지 않는다. 서버 권한으로 DB를 조작할 때도 매 요청의 사람·조직·방·binding을 검증한다. [키 근거](sources.md#s10)

private Broadcast/Presence 권한과 업무 테이블의 RLS는 별도다. 채널 이름만으로 보호되거나 private 옵션 하나로 모든 DB 행이 보호된다고 가정하지 않는다. [권한 근거](sources.md#s9)

개발 도중 만든 공개 preview URL에는 회사 데이터를 넣지 않는다. 실제 접근을 인증 없는 브라우저, 초대되지 않은 계정, 취소된 기기 토큰으로 검사한다. 플랫폼 Deployment Protection의 production 적용 범위도 별도 확인한다. [배포 근거](sources.md#s2)

## 가용성과 운영

- heartbeat가 끊긴 기기는 마지막 확인 시각을 표시한다. Presence는 실제 runtime 작업의 생존 증명이 아니다.
- 최대 기기·방·동시 run·대기열·메시지·산출물 크기를 제한한다.
- 업데이트는 프로토콜 호환성, active run 존재, 로컬 저널 호환 여부를 확인한다. 자동 업데이트로 실행 중 기록을 잃지 않는다.
- 토큰 취소·탈퇴·방 제거는 새 요청을 차단하고 기존 active run의 중단 확인을 추적한다.
- 데이터 보관 기한, 삭제 권한, 백업 복원 범위, 감사 기록 익명화/삭제, 공유했던 공급자 기록의 삭제 가능 범위를 정한다.
- 장애 지표: 요청 대기시간, UNKNOWN run, 중단 미확인, 재연결 빈도, 누락 backfill, 권한 거절, runtime 오류, 예상/실제 사용량 차이.
- 로컬 로그 수집은 사용자가 고른 진단 자료로 시작하며 비밀을 포함할 수 있는 원본 로그의 자동 업로드를 기본으로 하지 않는다.

## 비용과 사용 한도

| 항목 | 추정에 필요한 입력 |
|---|---|
| AI 호출 | 모델·입출력 token·context 크기·왕복 수·설명 대화·실험 재작업 |
| Vercel | 초기 Hobby 한도·Function 사용·전송; 후속 업무용 확장 시 플랜·좌석·보호 기능 |
| Supabase | DB compute·보관량·백업·Auth·Realtime 메시지/최대 연결·egress |
| 로컬 | 설치·업데이트·CPU·메모리·개발자 지원 시간 |
| 운영 | 문제 대응·보안 검토·공급자 업데이트·장애 복구 |

전체 대화 반복 주입과 모든 token의 fan-out은 context와 전송 비용을 키운다. 관련 질문·요약·근거만 전달하고 확정 기록과 임시 표시를 구분한다.

실제 API 사용량과 구독 소비를 같은 단가로 환산하지 않는다. 호출 수·시간·동시성 제한은 제품에서 강제할 수 있지만 공급자가 token/금액 hard cap을 제공하는지는 별도다. 완료 후 보고된 사용량과 실행 전 예상값을 구분하고 ‘예산 초과가 절대 없다’고 표시하지 않는다.

사용자가 확인한 초기 용도는 개인·비상업용이다. Vercel Hobby + Supabase Free의 무료 한도 안에서 운영하는 것을 목표로 한다. 실제 사용량과 공급자 정책은 변할 수 있으며 AI 비용까지 무료라고 가정하지 않는다. 향후 회사 업무용으로 확장할 때는 해당 용도의 플랜 적격성을 다시 확인한다. [Vercel 플랜](sources.md#s2), [비용 근거](sources.md#s11)

## 무료 플랜 운영 기준

다음 수치는 **2026-09-30 공식 자료 확인값**이며 실제 배포 계정의 다른 프로젝트와 합산되는 항목도 확인한다. 두 사용자 MVP가 한도 안에 들어갈 수 있다는 판단은 설계 예상이며 부하 측정 결과가 아니다.

| 서비스 | 확인한 무료 한도·제약 |
|---|---|
| Vercel Hobby | 월 Function 호출 100만 회, Active CPU 4시간, Provisioned Memory 360 GB-hours, Fast Data Transfer 100GB |
| Supabase Free | DB 500MB/프로젝트, 파일 저장 1GB, 월 egress 5GB, Realtime 월 200만 메시지·동시 최대 200연결 |
| Supabase 휴면·복구 | 1주 비활성 후 프로젝트 일시정지 가능. 무료 플랜에 자동 DB 백업·PITR이 포함되지 않음 |

수치의 적용 단위와 최신값은 [공식 요금·사용량 문서](sources.md#s11)를 기준으로 한다. 월 200만 메시지는 AI 대화문 200만 개를 뜻하지 않는다. Broadcast는 발신 1건과 구독 client별 수신을 합산하고 Postgres Changes는 수신 client별로 집계한다. Presence도 사용량에 포함된다.

- **초기 규모:** 사람 두 명·AI 두 개·한 번에 공동 조사방 하나. 필요한 방만 구독하고 사용하지 않는 탭·채널은 해제한다.
- **임시 출력:** 공개 가능한 preview를 0.5~1초 단위로 묶는 것을 초기 제안으로 한다. 매 token의 DB 저장·API 호출을 피하고 payload 크기도 제한한다. 제어 요청과 확정 메시지는 이 묶음 지연 대상이 아니다.
- **영속 기록:** 최종 대화·질문/답변·실행 상태·필요한 코드 근거를 저장한다. 레포 전체·원본 대용량 로그는 자동 업로드하지 않는다. 저장량이 부족해도 아직 실행 중인 기록·멱등 키·복구 근거를 삭제하지 않는다. 오래된 완료방의 내보내기·삭제는 사용자에게 범위와 영향을 안내한다.
- **연결 유지:** heartbeat·lease 갱신·미처리 요청 조회도 사용량에 포함해 계산한다. idle 상태에서는 backoff를 사용하되 실행 중 lease의 유효성·중단 확인을 희생하지 않는다. 예상치와 공급자 usage 화면의 실제치를 대조한다.
- **한도 접근:** 임시 preview 빈도를 먼저 낮추고 필요한 제어·확정 기록의 여유를 남긴다. 여유가 부족하면 새 자동 조사를 시작하지 않고 이유를 안내한다. 진행 중 실행은 기존 중단·저널·UNKNOWN 규칙으로 처리하며 기록 성공을 확인하지 않고 완료 처리하지 않는다. 플랜을 자동 유료 전환하지 않는다.
- **휴면·백업:** 휴면을 막기 위한 가짜 트래픽을 만들지 않는다. 재접속 시 프로젝트 일시정지 여부와 운영자의 복구 절차를 안내한다. 중요한 확정 기록은 접근 권한을 지키는 내보내기·별도 백업 경로를 마련하고 복원을 확인한다.

이 기준은 호스팅·DB 무료 한도를 관리하기 위한 설계 제안이다. 기존 AI 구독 활용 가능성이나 API 사용료는 [AI 인증과 비용](ai-runtime-integration.md#인증과-비용--우선-확인할-제약)에서 별도로 검증한다.
